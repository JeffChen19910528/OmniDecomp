# Supported formats

"Verified" = covered by automated tests with self-built samples in `crates/testsamples`. Real-file runs were manual spot checks, not part of the test suite.

| Format / arch | Status | Notes |
|---|---|---|
| PE32 / PE32+ headers, sections, entry point | verified (PE32, PE32+) | Strict: a section whose raw data extends past EOF is rejected as truncated. |
| PE exports and imports (by name / ordinal) | verified on PE32+ sample; spot-checked on kernel32.dll and notepad.exe | Forwarded exports have no address. Bound and delay-load imports are NOT read. PE32 import thunk path is untested. |
| ELF32/64 headers, sections, entry point | verified (ELF64 LE, ELF32 BE) | Extended section counts (shnum = 0 with overflow in section 0) not handled. |
| ELF `.symtab` / `.dynsym` | verified on ELF64 LE sample only | ELF32 symbol layout untested. Section/file symbols skipped. No version info. |
| x86 / x86-64 disassembly via iced-x86 1.21.0 | verified (x86-64); 32-bit decode untested | Linear sweep; data in code is decoded as instructions; Intel syntax. |
| Functions and cross-references (x86/x86-64) | verified on a self-built ELF64 sample; spot-checked on notepad.exe | Functions = entry point + function/export symbols + direct call targets. Sizes unknown. Indirect calls, jump tables and tail calls are not resolved. Xrefs are medium confidence because linear sweep can decode data as code. |
| CFG (basic blocks) and call graph (x86/x86-64) | verified on self-built ELF64 samples; spot-checked on notepad.exe | Per-function CFG follows fallthrough, direct branches and jumps. With a `.pdata` range it stays inside that range; without one, direct jumps to other known function starts are treated as tail calls (a tail-call target nobody else calls is absorbed into the graph). Call-graph callers are attributed by `.pdata` size when known, else to the nearest preceding function start. Indirect jumps and jump tables are not resolved. Output: text, JSON, DOT. |
| Function sizes from ELF `.eh_frame` | verified on self-built ELF64 samples (pc-relative sdata4 FDEs, ordering, duplicates, zero sizes, limit, corruption); spot-checked on libclrgc.so and libcoreclr.so (x86-64 Linux, no overlaps among sized functions) | Reads CIE `zR`/`L`/`P` augmentations and FDEs; only absptr and pc-relative bases with fixed or LEB128 formats; 64-bit record lengths, indirect/datarel/funcrel encodings and CIE versions other than 1/3 are skipped. `.eh_frame_hdr` and `.debug_frame` are not read. Functions without an FDE (e.g. hand-written asm) have no size. |
| PE debug directory (PDB path, GUID, age) | verified on self-built PE32+ samples (decoding, control-character sanitizing, absent directory, corruption); spot-checked on Windows system DLLs | Reads the first CodeView `RSDS` record only (PDB 7.0). Informational: no PDB lookup, download or parsing. ELF build-id and PE32 samples are not verified. |
| Function sizes from PE x64 `.pdata` | verified on self-built PE32+ samples (ordering, chained-fragment skipping, limit, corruption); spot-checked on notepad.exe | PE32+ x64 only. PE32 and ARM have no size source, so sizes stay unknown. Unwind-info version/indirect forms beyond the chain flag are not interpreted. |
| Mach-O thin 32/64-bit, LE/BE: header, segments/sections, `LC_MAIN` entry, `LC_SYMTAB` symbols | verified on a self-built x86-64 Mach-O (fields, symbols incl. imports, limits, corruption, fat refusal) | No real Mach-O file spot-checked. Fat/universal binaries are refused (exit 12) with a message to extract one slice. `LC_UNIXTHREAD` entry, dyld info/exports trie, code signatures and `__eh_frame`/`__unwind_info` are not read, so there are no function sizes. |
| AArch64 disassembly via yaxpeax-arm 0.4.0 | verified on hand-encoded instructions (bl/b/b.cond/cbz/br/blr/ret targets and flow), partial-word handling, a 50,000-word pseudo-random decode run, and an AArch64 ELF end to end (disasm, functions, report) | Linear sweep; no real AArch64 binary spot-checked. 32-bit ARM / Thumb is NOT supported (refused with exit 13). Functions come from entry, symbols and direct `bl` targets only; there are no size sources for AArch64 unless the file has `.eh_frame`. |
| Report export: JSON, text, CSV, HTML | verified on a self-built ELF (all four formats, `--output`) | CSV cells starting with `=`, `+`, `-`, `@` are prefixed with `'`; HTML is escaped, has no script and a CSP of `default-src 'none'`. |
| .NET metadata (`dotnet` command) | verified on a hand-laid PE32+ sample (assembly, reference, TypeDef/MethodDef, limits, corruption); spot-checked on System.Private.CoreLib.dll and System.Linq.dll (.NET 8) | Reads CLR header, metadata root, `#~`/`#Strings` and the Assembly, AssemblyRef, TypeDef, MethodDef tables (row sizes for all tables 0x00-0x2C). No IL decoding, no signatures/generics, no resources, no C# output. Non-.NET files exit 12. |
| Java `.class` structure (`java` command) | verified on a hand-built class (Java 8) and on a class compiled by the local JDK 25 (spot check); corruption tests | Version, class/super/interface names, fields, methods, access flags, SourceFile. Bytecode is not decoded; attributes other than SourceFile are skipped. JAR/ZIP archives are refused (exit 12). |
| Optional decompilers: ilspycmd (.NET), CFR (Java) | `engines list` detects them; `decompile` can run them through an enabled plugin (manifests in `plugins/`) | Never run by detection. `decompile` starts the program only for an enabled plugin and with `--allow-external-exec`. Verified with a stand-in engine and, manually, with the real ilspycmd 11.1.0 on .NET assemblies (Windows). Java `.class` input was also verified manually with the real CFR 0.152 (through a hand-built `cfr.exe` launcher around the jar, Windows, classes compiled by JDK 25 with and without `--release 17`). |
| Strings | ASCII only | UTF-16 not extracted. |
| Decompilation | only via external engine plugins, .NET and Java only | Native code is refused (exit 12). Output is third-party text, untrusted. JAR/ZIP input is not supported. |
| 32-bit ARM, WASM, RISC-V, DEX, JAR archives | not supported | 32-bit ARM and RISC-V machine types are reported by `info`, but `disasm` refuses them (exit 13). Other magic gives exit 12. |
