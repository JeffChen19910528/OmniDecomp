# Roadmap
- Phase 0: environment check, stack decision, docs, ADR, acceptance tests (this change).
- Phase 1: core model, PE/ELF info, x86/x64 disassembly, strings, JSON/text CLI, limits, fuzzing.
- Phase 2: engine registry, symbols/functions, reports (JSON/text/CSV/HTML), CFG and call graph, AArch64, Mach-O: done. .NET metadata and Java class structure: done (native, no external tools). C#/Java source decompilation: engines are detected only; a `decompile` command is open (Phase 4).
- Phase 3: desktop GUI (egui, see ADR 0002): file info, functions/symbols/strings lists, disassembly, hex view, search, cross-references, themes and font settings, background loading with cancel. Also native file-open dialog (rfd) and graphical CFG / call-graph tabs (layered layout in `viewmodel::graph`). Done; pixel appearance and the real OS dialog are verified manually only.
- Phase 4: plugin layer (`crates/plugins`, docs/PLUGIN_API.md): manifest validation, enable/disable with pinned hashes, API/host version checks, built-in capabilities as plugins, `plugins list|enable|disable`, `decompile` driving an enabled external engine (ilspycmd / CFR manifests shipped, engines not bundled). Done and tested with a stand-in engine; real ilspycmd 11.1.0 verified manually on .NET assemblies and real CFR 0.152 on Java classes. GUI integration (Plugins and Decompile tabs, per-run consent window, built-in plugins gate opening files) added afterwards and tested headlessly plus once with the real ilspycmd through the same calls; not done: OS sandboxing, Java JAR input, JVM/.NET plugins for other runtimes.
- Phase 5: seeded mutation regression over the whole pipeline (330k mutated inputs in debug mode with overflow checks, no panic), resource-limit tests, CycloneDX SBOM + license table (`scripts/sbom.py`), reproducible zip packaging with hashes and version info (`scripts/package.py`) with an automated smoke test of the unpacked package, `docs/INSTALL.md` (install, upgrade, uninstall, troubleshooting). GUI language switch (English / Traditional Chinese, system CJK font, no bundled font). Windows x86-64 and Linux x86-64 (Ubuntu 24.04, glibc 2.39+) packages built and smoke-tested; macOS only cross-compile-checked, never run; CI workflow written (`.github/workflows/ci.yml`) but never executed; no coverage-guided fuzzing; binaries are unsigned.
